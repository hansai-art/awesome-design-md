# Awesome DESIGN.md

把一份 `DESIGN.md` 複製到你的專案裡，再告訴 AI agent：「幫我做出像這個網站一樣的頁面」，就能更容易產生真正貼近原始風格的精準 UI。


## 什麼是 DESIGN.md？

[DESIGN.md](https://stitch.withgoogle.com/docs/design-md/overview/) 是 Google Stitch 推出的新概念：用純文字描述設計系統，讓 AI agent 能讀懂並產生一致的 UI。

它本質上就是一個 markdown 檔案。不需要 Figma 匯出、不需要 JSON schema，也不需要特殊工具。只要把它放進專案根目錄，AI 程式代理或 Google Stitch 就能立刻理解你的介面應該長什麼樣子。Markdown 也是大型語言模型最容易閱讀的格式，因此幾乎不需要額外解析或設定。

| 檔案 | 由誰讀取 | 定義什麼 |
|------|----------|----------|
| `AGENTS.md` | Coding agents | 如何建置這個專案 |
| `DESIGN.md` | Design agents | 專案應該呈現的視覺風格與體驗 |

**這個 repo 提供可直接使用的 DESIGN.md 檔案**，內容萃取自真實網站。

## 每份 DESIGN.md 內含什麼？

每份檔案都遵循 [Stitch DESIGN.md 格式](https://stitch.withgoogle.com/docs/design-md/format/)，並額外補充以下延伸章節：

| # | 章節 | 內容重點 |
|---|------|----------|
| 1 | 視覺主題與氛圍 | 情緒、密度、設計哲學 |
| 2 | 色彩盤與角色 | 語意名稱 + HEX + 功能定位 |
| 3 | 字體規則 | 字型家族與完整層級表 |
| 4 | 元件樣式 | 按鈕、卡片、輸入框、導覽列及其狀態 |
| 5 | 版面原則 | 間距尺度、格線、留白哲學 |
| 6 | 深度與層級 | 陰影系統、表面階層 |
| 7 | 應做與避免事項 | 設計守則與反模式 |
| 8 | 響應式行為 | 斷點、觸控目標、折疊策略 |
| 9 | Agent 提示指南 | 快速色彩參考與可直接使用的提示 |

每個網站都包含：

| 檔案 | 用途 |
|------|------|
| `DESIGN.md` | 設計系統本體（agent 會讀的內容） |
| `preview.html` | 顯示色票、字體尺度、按鈕與卡片的視覺目錄 |
| `preview-dark.html` | 使用深色表面版本的相同目錄 |

## 新手教學

如果你是第一次接觸 `DESIGN.md`，可以照下面流程開始：

1. **先選一個接近你產品風格的網站**
   - 從上面的清單中挑一個最接近你想做的產品。
   - 例如做 SaaS 後台，可以先看 Linear、Stripe、Supabase。

2. **打開對應的 DESIGN.md**
   - 點進網站連結後查看內容。
   - 觀察它的色彩、字體、按鈕、卡片與版面描述是否符合需求。

3. **把 `DESIGN.md` 放進你的專案根目錄**
   - 檔名維持為 `DESIGN.md`。
   - 這樣 AI agent 在產生 UI 時，就有明確的視覺依據。

4. **告訴 AI 你要做什麼頁面**
   - 先清楚描述頁面用途，例如登入頁、產品首頁、後台儀表板或定價頁。
   - 再要求 AI 依照 `DESIGN.md` 的風格製作介面。

5. **先做一頁，再逐步調整**
   - 第一版先看整體方向是否正確，不要一開始就要求所有細節。
   - 如果顏色、字級或元件風格不夠像，可以請 AI 重新對齊 `DESIGN.md` 的規範。

6. **遇到不一致時，直接回頭修改提示**
   - 如果 AI 做出的 UI 太花或太樸素，就指出你要它更貼近哪個段落。
   - 例如指定它加強色彩層級、減少陰影、或遵守更嚴格的字體階層。

### 最簡單的使用方式

1. 複製一份網站的 `DESIGN.md` 到你的專案根目錄
2. 告訴 AI agent 要依照這份設計系統產生畫面
3. 檢查結果後，再逐步追加需求與微調風格

## 如何使用

1. 把某個網站的 `DESIGN.md` 複製到你的專案根目錄
2. 告訴你的 AI agent 使用它
